# Water Quality Prediction: Explainable Machine Learning and Uncertainty Analysis

A three-phase machine-learning project for analysing water-quality measurements from four South African sampling locations and predicting **`Prec. Potential`** from **`pH`**.

> **Project status:** Research / internship capstone. Results and methodological choices should be independently validated before operational use. The source dataset is not included in this repository; add it only if you have permission to share it.

## Project objectives

1. Clean and explore the water-quality dataset, investigate missingness, impute missing values, and identify potential outliers.
2. Rank candidate input features by their correlation with `Prec. Potential`; the current modelling workflow uses `pH` as the sole predictor.
3. Compare regression models, including Support Vector Regression (SVR), Decision Tree, Artificial Neural Network (MLP), and CatBoost.
4. Evaluate model performance with R², RMSE, MAPE / related error metrics, median absolute error, and explained variance.
5. Explain predictions with SHAP.
6. Visualise model behaviour and station-level patterns for Vaalkop Raw, Klipdrift, Wallmannsthal, and Cullian Raw.
7. Explore prediction uncertainty using bootstrap resampling and Monte Carlo perturbation of pH measurements.

## Notebook workflow

Run the notebooks in this order:

1. **`01_data_preprocessing_feature_selection.ipynb`**  
   Loads and inspects the raw data, analyses missing values, performs imputation and outlier handling, creates visualisations, and saves `final_cleaned_dataset.csv`.

2. **`02_model_training_evaluation.ipynb`**  
   Loads `final_cleaned_dataset.csv`, trains and tunes SVR, Decision Tree, ANN (MLP), and CatBoost regressors, compares their performance, and creates evaluation plots.

3. **`03_explainability_station_insights_uncertainty.ipynb`**  
   Re-fits the selected SVR model, performs SHAP-based explanation, visualises station-level prediction patterns, and explores bootstrap and Monte Carlo uncertainty.

## Evaluation metrics

- **R²:** goodness of fit relative to predicting the target mean.
- **RMSE:** penalises larger prediction errors and is expressed in the target's units.
- **MAPE:** percentage error; it can be unstable or undefined when actual target values are zero or close to zero. Consider reporting sMAPE or MAE alongside it.
- **MdAE / median absolute error:** robust summary of the median absolute prediction error.
- **VAR / explained variance:** proportion of target variability explained by the predictions; this is not the same as statistical variance of the target.

Use the exact metric definitions and names reported in the notebook outputs when presenting results.

## Important methodological notes

- A high correlation between `pH` and `Prec. Potential` does **not** by itself prove that `pH` is the best predictor or guarantee generalisation. Compare feature selection inside the training data and validate on held-out data.
- The Phase 1 workflow performs imputation and outlier handling before the train/test split in Phase 2. This can cause information leakage. For a stronger final submission, fit preprocessing steps using training data only (ideally with a scikit-learn `Pipeline`) and apply them unchanged to validation/test data.
- The Phase 2 notebook uses a random train/test split. If observations are repeated over time or grouped by station, consider a time-aware or group-aware validation design and report how it changes performance.
- Phase 3's station-wise descriptive plots use predictions generated across the cleaned dataset. Do not label those as independent test-set performance unless metrics are recalculated on held-out observations for each station.
- The notebooks contain written interpretations and reported values. Re-run all cells from top to bottom and verify that the displayed results match the current data and code before sharing with a company.
- Predictions from a one-feature model are limited: pH alone may not capture all physical and chemical processes that influence precipitation potential. Treat results as exploratory, not as a replacement for laboratory measurements or domain review.
